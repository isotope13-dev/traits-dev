# Android APK mislabeled-bad review

Review in progress: the snapshot contains 40 packages, all initially labeled
bad. Labels and filenames are leads, not proof. Small-package scans from both
local scanners are in `/var/tmp/triage-android-{cleave,atom}-small.jsonl`;
medium-package scans use the corresponding `-medium.jsonl` files. DEX and
manifest inspection is static; no sample was executed.

- `2652bd208ccd07637d7be824570290e700d8d6eb39193c431948bcf17af4a19c` — **bad** — The app presents a justice-themed interface and registers an SMS receiver. Its legacy `android.telephony.gsm.SmsMessage` code reads received sender and message bodies, stores both in receiver fields, and launches a nested task that puts those fields in JSON and writes an HTTP POST body. Existing DEX rules missed the older SMS class and display-message accessor; those are now covered, and a separate rule combines the nested POST task and nearby SMS, JSON and HTTP call sites. Both scanners now report hostile evidence. Six size-preserving negative DEX mutations and full validation passed; Hopper confirmed the label.

The receiver attempts to start a process at boot. Static disassembly shows that its `Runtime.exec` argument array mistakenly places a URL in the executable position, so this packaged command does not launch as written; the manifest also lacks the Internet permission. A hostile finding combines the boot action, fallback downloader command and process call while describing them as clues, not successful execution. Both scanners report it; five negative DEX mutations and full validation passed. Hopper confirmed the label.
