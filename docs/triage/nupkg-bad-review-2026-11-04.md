# NuGet mislabeled-bad review — 2026-11-04

Reviewed 40 packages with Cleave and Atom and inspected embedded build hooks, scripts and binaries. The resulting classifications are 16 bad, 15 good and 9 inconclusive.

`1854a2371a28` is a dependency-confusion PoC that automatically sends build-host and pod names to a webhook. Both scanners already report it as hostile, regardless of its authorization disclaimer. `9606c3e7ef10` contains another automatic build hook that attempts to send the build user to a collaborator endpoint. Both scanners now report the package and its extracted target as hostile; an altered identity-expression control clears. Its `$(whoami)` syntax may be consumed as an MSBuild property before the shell sees it, so the rule describes an attempted callback rather than claiming the user name is successfully transmitted.

`3b243c13df0a` is a gated Chocolatey install hook that posts npm and NuGet credential files. `8774b9183b16` is a gated clipboard cryptocurrency-address replacer. `2697e782b5eb` resolves commands through public-service and blockchain dead drops and executes a decoded shell stage. Existing hostile findings match each in both scanners.

`3756bd37307b`, `a6ce713e3031`, `727ac0a1e31e` and `206af1064141` contain managed UI libraries with device-identity enrollment, HTTP backchannel and file-upload behavior. `dfb14ff05e12` contains a clock library with a URLMon download and rundll32 launch. `80e98249cb45` claims to provide drawing APIs while its automatically imported build targets run conditional cleanup tasks against the consuming project. Existing hostile findings identify these behaviors in both scanners.

`6ae4323a9315` is bad because its managed DLL combines resource decoding, XOR and reflective invocation. The same installer also contains ordinary PowerShell runtime and NetFilter SDK driver components. A prior AMSI finding inferred a memory patch solely from unrelated API references, and two third-party signatures labeled a vulnerable SDK driver as a rootkit. Those findings are now suspicious rather than hostile; both scanners retain the DLL's separate hostile obfuscated-loader findings. Presence of the vulnerable driver alone does not establish malicious use.

`d0d44173c4b1` and `119685fc2691` are hostile UI-helper libraries. Their initialization path extracts an embedded ZIP, reflectively invokes a DLL that empties C# files and can close Visual Studio, and launches an embedded batch file that recursively deletes files. The parent libraries and extracted wiper now match in both scanners; an altered control clears. `24f62ca3e132` and `5f9bfee456be` contain the same embedded browser-policy loader inside a managed clicker resource. It combines Chrome extension force-install policy, executable download, scheduled task configuration and a rundll32 loader. Both scanners now detect the packages and embedded bytes, and a policy-modified control clears.

`c147e43aafb2`, `e098f2e9799e`, `9ffb7f190b44`, `c1a61ff102bc`, `7d487b503a5b`, `f30d32a6dc00`, `c7c40095243d` and `184c15bc00d4` are inconclusive. Their related managed programs obtain an executable from multiple remote locations, use DNS over HTTPS and launch through a command shell; some also use a hidden PowerShell time-synchronization command. A new suspicious finding combines the observed facts without asserting that the unavailable downloaded executable is malicious. Static IL inspection showed a user-visible asset-download workflow and executable launch; the downloaded payload itself was unavailable for assessment.

`af42caca1f4d` is also inconclusive: this WebSocket bridge contains an actor that can run supplied PowerShell after a monitored file changes, but the review did not establish whether the bridge connects remote input to that actor by default or how callers expose it. The existing suspicious finding describes the script runner.

The remaining packages were classified good: `8de9215b0332`, `440d7169cceb`, `4afef629fb58`, `bb90aa68eee2`, `89d8448b4b08`, `65af732a725e`, `d9bb8158c134`, `833979f3a9b0`, `7efa3152e171`, `ac32826dd63b`, `8c95b7da1f91`, `655c48c312ec`, `887fba95de05`, `7ccaeabeb1be` and `833d0e0dbe2e`. Review corrected misleading findings for a PowerShell error string mistaken for a URL, Wi-Fi profile creation mistaken for harvesting, generic network and camera APIs, and an ordinary agent output instruction mistaken for prompt injection. The CSV mail utility retains one suspicious finding for accepting all TLS certificates, and the onboarding utility retains one for a hidden scheduled task.

The updated rules were checked with both scanners and targeted altered controls. Full `make validate` passed. Hopper confirmed all classification moves.
