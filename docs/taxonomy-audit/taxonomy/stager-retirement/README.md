# Legacy stager retirement

The final 26 rules in `objectives/command-and-control/dropper/staging/stager`
were reviewed and moved, retiring the last `dropper/staging` namespace.
Python configured binary fetch-and-launch chains are grouped by their spawn
sink; helper names and weak process/PE co-occurrences are classified as source
names or process profiles. ROR13 network and executable-memory combinations
remain admitted payload acquisition observations with their original hostile
severity. The Linux get-PC and executable mmap combination is a memory
profile, since those observations do not establish a staged payload.

A Delphi/Inno co-occurrence and an unsigned PE with embedded executables no
longer claim specific malware ownership or payload drops. Compact ELF network
syscall combinations are socket profiles, and configuration field matches are
configuration profiles. Eight rules were reduced to suspicious or notable
because the original evidence did not support the old hostile or suspicious
claim; their matching conditions and effective defaults otherwise remain the
same. The Shikata Ga Nai decoder combination remains under its obfuscation
mechanism.

The legacy staging directory consumer now lists applicable migrated members
explicitly. The hosts-file consumer retains the prior alternatives, using two
directory selectors only where they cover exactly the same present members.
Those selectors need review when their directories grow. Existing historical
ancestor-consumer audit notes still apply.
