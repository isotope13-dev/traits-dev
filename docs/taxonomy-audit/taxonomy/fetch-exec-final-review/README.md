# Remaining fetch-and-execute review

The remaining legacy fetch-exec rules now follow their supported activation,
quarantine-bypass, package-hook, or evidence subjects. A concatenated
`GetObject` URL does not establish a scriptlet, and an off-screen HTA with a
scheme fragment and DOM append does not establish a remote script. Those rules
now describe their observations. Interleaved command text and percent-encoded
shell text are profiles unless an execution chain is supported.

The Ruby HTTP-body write and launch has a data-bound AST match but no separate
hostile context; it now belongs to neutral process deployment. Filename-only
test exclusions were removed, while content-based exclusions were retained.
The nearby in-process network-evaluation directory was divided by moving six
package initialization and installation contexts to `network/package-hook`.

The file-profile level also exceeded its subdirectory limit. Script evaluation
and transformation, COM observations, and tunnel observations now each have a
shared parent with subject-specific children. Network evaluation clues were
reviewed alongside their siblings and grouped together; existing directory
selectors and individual references were updated.

A Ruby download/write/launch chain with an encoded domain and world-writable
permissions retains a hostile finding. The neutral data-bound deployment rule
still matches ordinary deployments without independently hostile evidence.
