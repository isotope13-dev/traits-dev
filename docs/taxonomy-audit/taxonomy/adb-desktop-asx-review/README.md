# ADB, desktop-entry and ASX delivery review

Android temporary-path and ADB download-and-launch chains move to payload
execution by shell command. Desktop-entry launch chains move to that same
execution subject, except that the ordinary download-and-launch capability is
kept neutral and the document-icon disguise lives with masquerading.

The ASX rules only combine an HTMLView parameter, two short path fragments,
and PHP or request-variable clues. The fragments are components; the resulting
combinations are notable XML/ASX evidence, not proof that a GIF is a payload
or that a redirect was delivered. The former dropper-ancestor consumer keeps
the moved non-component alternatives explicitly. The two generic path
fragments no longer independently satisfy that hostile consumer.
