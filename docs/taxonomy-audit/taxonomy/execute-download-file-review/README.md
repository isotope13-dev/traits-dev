# Execute-download file review

The first file batch separates CI staging, native execution, embedded WSH commands, remote injection, indicator removal and encoded package payloads by behavior. CI step atoms remain under CI metadata, while the concealed temp-file combinations live with CI payload behavior. The Go and payload-worker log strings are diagnostic observations, and the associated combinations are named for the evidence they require rather than assuming a compiler or a particular family.

Several older descriptions asserted more than their matchers: process lookup did not name Explorer; function names did not establish Electron download and execution; a Run-key path and service API name did not prove persistence; WinVerifyTrust did not prove that the binary was signed; and URLMon, PE-header and protection references did not establish an executed in-memory stage. These are now described as observations or profiles, while chains with a more specific execution or evasion behavior remain objectives.

An empty Rust rule file was removed. The remaining C# file and its consumers need a separate product-identity and execution review.

The remaining C# batch has now been reviewed. Generic taskhost path, environment-name, update-method, HTTP and file-write observations moved to their subjects. Product-specific indicators moved under named malware evidence, and their family correlations moved with them so generic execution objectives do not require a malware identity. The generic GitHub downloader retains its behavior-based alternatives. The three FTP-banner rules previously referenced the legacy execute-download parent: its remaining generic observations were retained explicitly, while family-specific PE indicators were not inserted into generic objectives.

The WUDFhost URL appears in the [Dr.Web Trojan.DownLoader26.62086 report](https://vms.drweb.ru/virus/?i=17524810). A separately submitted file named svchost.zowner was observed performing stealer-like activity in [ANY.RUN](https://any.run/report/5aebca345f3cc7fd0251092cce5682d68391fbd5b5c232c393c58082f0347a72/9a4c64b3-ebad-413f-9875-c7850dab8c15); the matching name alone does not establish that the hosted URL serves that exact submission. The URL and name are retained as observations, not proof of that connection.

The legacy file leaf and execute-download parent are retired. The matching obsolete broad-file-type exemption was removed from the Cleave validator. Family indicators retain all-section matching and use a one-byte minimum, avoiding an arbitrary upper size limit.
