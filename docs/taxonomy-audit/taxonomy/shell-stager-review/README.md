# Shell stager review

The legacy shell group mixed file operations, source generation and activation.
The architecture copy and directory write test now describe their file-system
operations. Command substitutions that execute fetched text are deployment
behaviors; the direct-IP variants remain admitted payload execution. Generated
source fragments and a generic command-runner generator are payload-building
profiles, while the two remote-shell generators reconstruct a payload. Source
written as configuration is staging storage; the two local execution chains
are filed under their shell-command sink.

All 17 rules retain their effective defaults, match conditions, exclusions and
severity. The `bash-c-curl-ip-loader` description now says `sh`, matching its
required trait. The existing hosts-file consumer used the entire legacy dropper
namespace; explicit references preserve its previous alternatives. Its broad
historical alternatives remain subject to the separate dropper-consumer audit.
The Python-only staged-loader selector cannot match the moved shell-only rules.

The neighboring network script-evaluation category was approaching the
80-trait target. Seven blockchain-derived code or destination rules moved into
`script-eval/blockchain`, leaving 67 rules in `script-eval/network` after the
two shell additions. Existing explicit references were updated; no rule cap
was changed.
