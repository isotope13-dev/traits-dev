# Node archive and directory-reference review

The two Node bootstrap rules that referenced the entire legacy archive directory now name extraction-specific JavaScript, PowerShell, passworded-archive and WSH observations. The older directory reference could satisfy an extraction claim using an archive constructor, a filename or other unrelated staging clues. The revised component still includes separately named ISO context alternatives, so its description makes that broader meaning clear. The library-or-extraction aggregate is also described honestly. Actual extraction can now match directly without requiring an unrelated staging composite.

Eighteen rules moved: archive constructor and exit clues, extraction/walk and HTTP/decrypt profiles, passworded extraction, COM ZIP and WSH observations, a PowerShell archive command, and six Node bootstrap or exception rules. Constructor/exit and separate network/decrypt clues do not establish execution; likely encoded launch chains remain execution objectives. Node module-call/detached-child observations belong with daemonization. The named React Native exception moved under its product.

A test-directory exclusion was removed from the Node archive profile and PowerShell extraction observation. Source-map and unrelated named-software suppressions were removed from the factual extraction/password observations. This intentionally broadens those observations. Other matching predicates, scopes, confidence values and suppression gates were preserved.

The Node bootstrap directory was reduced from 77 to 71 rules as part of this move. ISO-related alternatives are retained pending their own taxonomy review.
