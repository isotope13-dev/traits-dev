# Update-rule review

An Android update prompt, HTTP API and installer request that asks for no user
action describe an update/install capability; the request can still require
confirmation and does not establish a fake update. A tokenized update path with
curl output and a temporary path describes a probable fetch, not a payload.

WwanSvc update paths, Window Update text and the command status format are
weak binary-text components. They remain unbounded observations because those
strings alone do not establish family ownership. Their combined update and
registry clues live under the Rifle family, and the existing family consumer
retains the same Window Update match. Broader update directories and
success/failure wording remain generic.

Update endpoint strings, batch move and self-delete text, and their combined
network-update clues moved to their respective subjects. The combination can
indicate an updater, but does not by itself prove that an unsigned updater is
malicious, that a downloaded file was executed, or that the move replaces the
running executable. Existing predicates and exclusions remain unchanged.
