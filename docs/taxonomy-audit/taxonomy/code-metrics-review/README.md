# Code metrics review

Function-size measurements belong to the function-population profile; the
digit-heavy, low-whitespace text with a long line and an XOR expression is a text-distribution
profile. Neither proves an obfuscation mechanism. Existing consumers of the
latter now refer to its new ID. The VS Code extension marker belongs with
VS Code bundle observations, while the QuickLook MarkdownViewer resource name
is a product-specific observation.

Four unreferenced component groupings for recognized long strings, multiline
blobs and few strings were retired. They were collections of unrelated
exceptions, had no consumers, and did not establish an objective. Their
individual referenced observations remain. The QuickLook text observation,
which was also a visible notable trait, remains under the product.

The identifier and function leaves were also reviewed. Function nesting and
identifier density are measurements; generated-code, JRuby, AWS CDK and
Doxygen observations identify their subjects. PHP array syntax, Unicode
references, embedded image data and translation-call text moved to their
subjects. The PHP non-ASCII subscript is notable syntax, not inherently
suspicious; product-wide exclusions were removed while retaining the PHAR
exception for binary tails that can produce false text matches. Eleven
component-only suppression groups without external consumers were retired.
The utility-basename observation moved to the tool-reference profile.

The remaining standalone source-shape and selected structure rules were
reviewed by their matchers. Empty-line ratios, Python function and hex-string
counts, WinForms scrollbar names, and long lines with short function names are
measurements. BuildKit text and the `.pyz` basename identify their own
subjects; the basename does not establish an archive structure. The long-line
profile retains its prior decode-execution exclusion because it is itself
used as an exclusion, and broadening it would suppress additional results.
The execution-clue combination moved to an operation-cooccurrence profile;
its internal two-alternative grouping was inlined with the same alternatives.
Two unused long-line context groupings were retired.

Lua and JavaScript observations moved by their evidence: encoded candidate
populations and escape shapes describe text; proxy calls, indexed strings,
and load-symbol co-occurrences describe Lua source profiles. Those patterns
do not alone establish a loader, so their standalone claims are suspicious or
notable rather than hostile. A nearby character-reconstruction and direct
evaluation chain remains an execution objective. Consumers were updated.

The 86-rule encoding-shape leaf was split into high-bit (17), offset (31),
escape (10), fragment (18), and character (10) observations before adding
the JavaScript escape rule. Existing parent selectors remain recursive;
cross-leaf local references were made explicit.

The file-profile parent reached its subdirectory limit when the Lua profile
was added. Existing graphics API, capture, and context profiles are now
grouped under `graphics/`; their exact rule references were updated. This
reduces the width without changing the limit or broadening those selectors.

The remaining shell and native rules moved by their observed subject. Shell
syntax and source measurements are separate from evaluation, character
decoding, and profiles combining command-related clues. Split character and
escape evidence alone no longer claims a hostile command. Native byte
sequences and their density profile describe immediate arithmetic, with the
recovered UPX layout recorded separately. Existing consumers retain their
alternatives and the previous signature exclusion. One unused recognized-
context component and an empty placeholder file were removed. The legacy
code-metrics directory has no YAML rules or live YAML references.
