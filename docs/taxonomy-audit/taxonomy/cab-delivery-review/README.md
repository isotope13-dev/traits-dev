# Cabinet delivery review

Business-themed executable and script names retain their likely document impersonation objective; archive traversal, a system-DLL sideload candidate, manual mapping and explicit obfuscation follow their respective behaviors. Member names are observations in their own right.

A CAB containing an executable, runtime reference, default manifest, high entropy or ordinary script is not enough to establish a dropper. Those combinations are retained as suspicious archive profiles with descriptions matching the actual legs. Scope and suppressors remain unchanged. An empty archive cannot deliver a working payload.

The crowded archive-member filename leaf was divided by name subject before adding the cabinet clues. The legacy cabinet delivery directory is retired.
