# Network evaluation sink review

The 68-rule network script-evaluation leaf was reviewed and partitioned by
activation: direct interpreter or script loading, function-constructor
execution, and reconstructed response code. URL encoding and an obfuscated
evaluator do not by themselves mean the response was decoded. Four misplaced
observations moved to HTTP, markup, command-injection or non-network transformed
subjects. The resulting network leaves have 61, 13 and 10 rules.

Thirty-four rules moved out of the legacy remote-code directory, leaving 26.
Coherent execution chains use network evaluation, module loading, interpreter
stdin, file execution or command dispatch. Generic RSA/function, VM/fetch and
response/function co-occurrences are suspicious profiles rather than asserted
payload chains. A YouTube challenge context stays an exclusion-only metadata
exception: endpoint and configuration references do not establish vendor
ownership. Four overly strong profile findings were reduced to suspicious.

The old positive directory selectors excluded exception traits, so the YouTube
exception remains solely in its existing exclusion. The hosts-file and plugin
consumers retain the other 33 moved alternatives. The FTP-banner composites
already select all payload file-execution and interpreter-stdin rules; moving a
Node fetch/launch chain and an Axios-to-Node-stdin chain into those sinks makes
those two signals available to the existing FTP selectors. This is a deliberate
addition of staged execution evidence to those positive rules, not an
exclusion. Their existing type and proximity constraints still apply.

A comparison accounted for all 128 reviewed rules and preserved their matching
conditions and non-technique defaults. No cap changed.
