# Binder review

The C-source rules report an actual file-position call and ShellExecute open
syntax separately. Self-path, seeking, write-access open, and ShellExecute
co-occurrence does not establish appended records or a write; it is a
suspicious file-operation profile. The existing ShellExecute consumer was
updated.

Hash-resolved sandbox probes, overlay I/O, temp-path and process API references
are a suspicious overlay profile. Rust and UPX multi-PE overlay combinations
record their layout, packing or allocation-reference evidence without
claiming binding or payload execution. Existing platform-signature, installer,
and embedded-child exceptions remain attached.

The VB6 token-delimited executable URL is an observation, not proof of a
network download. VB6 overlay, binary-write and process-launch combinations
remain execution objectives because their combined evidence supports a likely
payload chain; their names describe the evidence without claiming the data
flow was observed. The older VB6 text-fragment rules still need review.

The remaining VB6 fragments moved to binary text, file-read, split, source
naming, declaration and operation-reference subjects. `Asc(Mid$` alone does
not establish XOR, and opening an EXE in binary mode does not establish a
write. Self-name plus binary-read clues remain a likely self-read capability;
root-path binary open and Shell text are a profile, and the combined self-read
and root-EXE shell pattern is a suspicious execution objective. File-bind
strings with service or recycler clues do not establish worm propagation.
The Incubus family rule still references its original three shared strings.

The operation-reference neighborhood was split to put evaluation text in
`eval-reference`; `script-evaluation` remains the home for evaluation combined
with other file context. Existing individual references were updated.
