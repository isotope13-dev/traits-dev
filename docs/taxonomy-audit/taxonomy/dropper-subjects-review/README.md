# Editor, AppData, character reconstruction and Elex review

Thirty-four rules moved out of four legacy dropper leaves. Editor-directory
fetch-and-run chains use the file-execution sink; their download, permission,
path and launch observations use the corresponding capabilities. AppData
write and process-start calls use their actions. A `File.Copy(fileName1,
environmentVariable...)` fragment no longer claims the source is self or the
target is AppData.

Character-array casts and joins are notable construction evidence. Decoded
ScriptBlock and WebClient names retain their specific operation subjects. A
batch combination that does not require evaluation is a suspicious profile;
the hidden XOR/character-code evaluation remains an execution objective.

The exact Elex-associated encoded fragments are notable observations in metadata, so the
hosts-file objective can refer to observations rather than malware identity.
Their combined identity remains under well-known Elex. The URL-regex, WMI and
WinHTTP heuristic is a suspicious network profile and no longer asserts Elex
identity from generic evidence. The pre-existing hosts-file dropper selector
retains the moved alternatives; its four raw Elex fragments already subsume
the former all-four composite.

The 91-rule string-concatenation leaf was divided into join, append and
expression. The 83-rule executable-mode leaf was reduced by moving hidden-path,
file-creation-mode and setuid observations to their subjects. Thirteen old
whole-directory consumers now use an explicit component roll-up of the old
mode leaf, the new hidden and creation leaves, and precisely the three moved
setuid facts. Future additions to those selected leaves need consumer review.
Six runner-environment/network profiles moved out of the 71-rule network leaf.
