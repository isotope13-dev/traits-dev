# FTP delivery review

FTP command-file retrieval lives with FTP client behavior. Short credentials
are not necessarily throwaway credentials, and an explicit numeric port does
not establish a raw IP or an ephemeral port. These combinations are notable
transfer evidence; saving an executable under Windows remains suspicious.

The batch FTP and executable-launch combination remains a suspicious probable
payload chain. Encoded VBScript running a hidden FTP command file is staged
acquisition; the FTP and AppCompatFlags combination follows its UAC-bypass
objective. Neither description claims a proven data flow.

The former BAT.Ftp identity matched only a quit line plus generic short-login
or explicit-port executable retrieval. Those observations do not identify a
malware family, so the rule is now a notable FTP behavior, with its quit atom
retained as a component. The old dropper ancestor consumer retains the moved
non-component findings. The FTP-client directory selector was reviewed: the
new transfer composites already depend on existing members of that directory.
