# Legacy module-loader review

Sixty rules moved out of the 82-rule legacy module-loading leaf, leaving 22
MSBuild rules for a further review. The batch rules include source fragments,
encoded text observations and partial operation clusters: these now live with
the observed strings, source syntax, encoding, decryption or module-loading
profiles. The more specific assembled payload chains moved to module-loading,
file execution or evasion objectives according to their activation behavior.
Network, embedded and transformed sources follow the documented module-load
partition.

Two overly strong claims were reduced to suspicious, and three generic Android,
.NET and PowerShell profiles no longer inherit unsupported technique mappings.
All matching conditions and other effective defaults were compared with the
originals. FTP-banner composites and the hosts-file consumer keep their prior
legacy alternatives through explicit references. Those historical alternatives
include weak observations and warrant a separate admission review; broadening a
new destination directory must not silently change them.

The native encrypted-DLL chain retains its existing 10 MiB size limit, which
was added to avoid generic API matches in larger installers and vendor clients.
The limit can miss larger malicious loaders; removing it safely calls for more
distinguishing evidence or a corpus review.
