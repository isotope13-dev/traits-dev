# Sideload and download review

The service-backed DLL rule now follows service persistence, Chromium ELF export names live with the Chromium library, and the concealed export/flattening combination follows DLL masquerade. Batch tar and background-start atoms live with their operations. PEM/embedded-data and archive-launch findings describe what their conditions require; certutil plus EXE/DLL path text is supporting evidence rather than proof of a sideloaded pair.

The reviewed downloader rules now follow HTTP tasking, Run-key persistence, self-deletion, remote source evaluation, Rundll32 or ShellExecute, as appropriate. LIZRD-specific tags and combinations live with the existing LZRD malware evidence. Empty HTML refresh, tiny PE HTTP/RWX and FNV/WinHTTP combinations are profiles where their conditions do not establish a payload launch or authenticated C2 relationship. The WSH XOR/ActiveX rule likewise describes its required observations rather than asserting RC4.

The legacy sideload traits file and the Python downloader file remain for separate review.

The remaining sideload leaf has now been reviewed. Cisco Spark, Broadcom Credential Vault, Office, Defender, Windows color management, CLR and Evernote markers live with their products; product filenames alone are notable or component evidence. Vendor version claims and generic DLL/name patterns are classified as such. The product identity rollups no longer suppress signed products, because signing does not negate the product reference.

Composites that actually combine proxy identity with suspicious signing or loader evidence follow DLL masquerade; the version-proxy hollowing chain follows process injection. Generic overlays, DLL names, Office PDBs, and importless layouts are profiles unless their conditions support a stronger objective. The sideload legacy directory is retired. Product observations use a one-byte minimum and all-section matching where required, preserving coverage without an arbitrary upper file-size bound.
