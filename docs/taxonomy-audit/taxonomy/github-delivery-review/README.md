# GitHub delivery review

GitHub attachment download, executable permissions, and local launch (or detached execution clues) remain in the file execution objective. The hosting service is a detail of the delivery chain.

The GitHub API switch and generic JSON SHA field are HTTP transfer evidence, not proof that a payload was fetched. WinHTTP, raw GitHub and Dear ImGui references do not establish a cheat or offset fetching. A native-library URL with file mode and permission clues does not establish execution. The GitHub blob endpoint with a nearby process or chmod reference does not necessarily establish a download-and-launch chain. These combinations are filed as evidence profiles with descriptions and severity matching their support.

The Windows rules split a Run-key persistence and download combination from its HTTP, DAT filename, executable-name and marker observations. Neither a common Update.exe reference nor a BlueLine_Ran.txt string proves persistence, execution, or marker gating. The DAT download combination is described as clues: a DAT suffix does not establish executable payload contents. This retires the legacy GitHub delivery directory.
