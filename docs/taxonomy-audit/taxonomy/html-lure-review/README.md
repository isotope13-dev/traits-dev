# HTML lure and page evidence review

Reviewed HTML rules now distinguish macro-document execution lures from page
text, download attributes, hidden iframe and remote-script observations. An
executor download title does not itself name Roblox, an HTTPS mirror is not
necessarily off-site, and a CloudFront query string does not by itself prove
tracking or malicious delivery. The associated page profiles describe those
clues without assigning unsupported family or execution claims.

A script filename in a download attribute does not establish that a download
occurred. The corresponding WSF, CMD and JavaScript atoms are now HTML markup
facts; combinations with forced download or data URIs retain their supporting
context as suspicious download profiles. The Dropbox-specific wording belongs
with Dropbox observations, while strong macro reopening and decrypted-document
lures remain under the macro-document execution objective.

The nearby 84-rule help directory was split into command, interaction, account,
message and navigation leaves. Existing recursive parent selectors, including
downgrades, continue to cover the same rules; the HTML Ctrl+O atom was not added
to that broad parent.
