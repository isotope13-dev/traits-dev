# Archive source and Node context review

Eighteen legacy archive and Node bootstrap rules moved by their actual evidence. The archive names, reported identifier and paired Google Drive URLs are observations; their combinations do not independently establish a loader or download. Rust consumers retain their separate process-launch and permission evidence.

Tar `-C` text, a tempdir/extract literal, recursive ZIP search, Recycle Bin/rename text and PowerShell process arguments now describe what their matchers observe. A combination of archive extraction and hidden/temp clues is an extraction behavior; a WebClient, archive extraction and process-launch combination remains an execution objective.

Four Node archive-library, extraction/ISO and temporary-path context rules moved out of legacy bootstrap to the archive profile. Their previously reviewed extraction alternatives and local consumers were updated without changing conditions. The legacy Node bootstrap directory now has 67 rules.

The reported-host profile and its four bounded host-name observations each inherited a 5 MB maximum. Both limits were removed: the observed host and archive names do not depend on total file size. Removing only the profile limit left every host leg unable to match above 5 MB. This intentionally broadens matching. Other predicates, scopes, confidence values, exclusions and downgrades are unchanged. Unsupported inherited technique annotations were removed where the rule does not establish the claimed action.

A 5,000,247-byte Python fixture now matches the host profile. Cleave reported that filefacts skipped the Python AST at its separate 4 MiB modeled-grammar safety guard; these migrated text predicates still matched. That scanner guard prevents unsafe parser behavior and is not a taxonomy rule limit.
