# MSI delivery review

The legacy MSI delivery category contained several different kinds of evidence.
The PDF decoy with a quiet remote MSI installation stays under installer
invocation, and the msi2exe script and process-creation chain stays under the
installer script execution sink. MSI download, archive expansion, elevation and
script-table observations are installation profiles; msi2exe identification is a tool-reference profile (its text match has no justified binary size or section restriction), and the sysupdate key reference belongs with registry paths.

A short certificate subject does not establish Azure Trusted Signing, and
Portuguese installer metadata does not identify a banking family. Their rules
now describe the observed installer evidence and are suspicious rather than
hostile. The certificate-store, HTTP and service capability conjunction also
no longer claims banker attribution. A sysupdate path and script references
alone do not establish persistence or a script launch.

The neighboring tool-reference directory was approaching the desired limit.
Its 30 Kinsing name and operation-reference profiles now have a dedicated
malware-reference namespace; they remain observations, not family attribution.
