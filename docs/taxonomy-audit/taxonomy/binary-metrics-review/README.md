# Binary metrics review

The cross-compiled, sparse-import and section-name leaves were reviewed by
what their rules actually establish. MinGW, TLS callbacks and API-hash
candidates are PE profiles; unsigned status does not alone make that profile
hostile. The libusb DLL basename moved to its library identity, without an
unrelated file-size threshold. Import density, section proportions, and
AutoIt/UPX combinations remain suspicious or notable layout profiles rather
than claims that a loader executed.

Slash-numeric sections with large zero-entropy regions describe PE layout,
which can arise from toolchains; size alone does not establish deliberate
inflation. Analysis-tool and taunting section names are observations, and
their combination is suspicious rather than a hostile verdict. Existing
exclusions and consumers were retained.

The section-label leaf had 82 rules and was split into conventional (36),
custom (16), and packing-related (30) names. The three analysis-related
name observations were placed in the existing neighboring section-name leaf,
so the label-directory downgrade retains exactly its former membership.
Parent-directory selectors remain recursive and cross-leaf references were
made explicit.

The import leaf was also retired. Import counts and aliased-export metrics
live under their measured subjects, with process and resolution combinations
kept as profiles. The former all-exports-aliased description required only
one alias and is now named accordingly; alias counts alone are notable rather
than proof of concealment. Library and runtime symbol names moved to their
subjects. Six unreferenced context wrappers were removed, including two
baseline groupings that did not require the import or alias property their
names claimed. Individual observations and active consumers remain. A synthetic missing-rule
placeholder became orphaned when the unused wrapper was retired and was also
removed.

Two crowded binary symbol-name leaves (89 and 93 rules) were split by the
subject referenced by the name: collection, execution, filesystem, network,
security, and runtime. This classifies the name evidence, not proof that the
named activity occurred. Cross-leaf references and existing recursive parent
selectors were preserved.

The profile, overlay and symbol leaves were retired. Injection API references,
PE parsing, unsigned overlay and resource combinations, and hidden-process
settings remain suspicious profiles where the rules do not establish a
payload or actual execution. The former hostile complexity and VM labels
were also corrected: their matchers combine complexity measurements, not
evidence of concealment or a virtual machine. Their consumers now reference
the measured complexity profiles. Existing suppressions were retained.

Selected remaining binary-shape rules were moved by evidence: PE section and
import layouts to structural profiles, direct socket/connect syscall
combinations to the socket capability, and the executable-stack credential
attack combination to the IoT credential-attack objective. The Mach-O
combination permits structural clues plus a single ordinary API, so it is a
section profile rather than an asserted stealer. String-count and entropy
measurements no longer claim deliberate junk padding.

Two tiny ELF rules and two dependent execution claims described stagers,
although their predicates require HTTP text, addresses, and file layout but
no network or execution operation. They now describe suspicious network-text
profiles. Existing meaningful predicates and suppressions were retained.

The PE profile leaf at 70 rules was divided by resource, process, network,
layout, and resolution evidence. The natural-language phrasing leaf at 85
rules was also divided by subject. Exact references were updated, and parent
directory selectors continue to include the same existing rules.

The final binary-shape rules were routed to section, overlay, embedded-file,
installer, API-resolution and packing subjects; the binary-metrics directory
now contains no YAML. Twenty-two unreferenced component groupings were
retired. A verified Microsoft signature plus a checksum mismatch and embedded
PEs is a suspicious profile, not proof of post-signing tampering; section
shape and checksum observations likewise do not establish hostile intent.
The existing directory-wide installer downgrades do not include the moved
7z/PKCS7 component, preserving their former membership.
