# Lifecycle, Bun and packed-PE review

Twenty-one distinct rules moved out of seven legacy dropper leaves. Python
write and process-launch roll-ups remain components at their evidence
subjects. Cloud URL plus status text, forwarding-DLL references, and MPRESS
layout/API combinations describe their observations instead of claiming an
executed payload. A hidden WinExec plus XOR-stage combination stays with
hidden launch, and the Node download/launch chain stays with its execution
sink. Bun host-profile fields and HTTP POST retain their probable information
stealer objective; Bun VFS, API names and unbound FFI/network combinations have
subject-specific homes.

A scripts-only proxy-loader composite required a PE-only forwarding-DLL trait
in file scope, so it could never match and was removed. Two MPRESS/Adobe/IP
composites were merged: the unsigned Adobe alternative was a strict subset of
the already-present Adobe version-claim alternative. Licensing APIs without
additional misuse evidence now describe a notable licensing capability; the
former benign-signature exclusions no longer hide that capability. An existing
Apps Script consumer selects the licensing directory only for JavaScript, so
the new PE/DLL-only rule does not expand its effective matches.

The hosts-file dropper ancestor consumer retains the moved alternatives. The
removed impossible rule had no effective matches; the merged rule retains the
broader original alternative. Thirteen overlay measurements moved to their
ratio, size and entropy subjects, and eight process-launch clues moved out of
the execution-API catchall. The overlay size observation no longer repeats a
file-size minimum already implied by its 1 MB overlay metric.
The hosts-file consumer now receives the licensing capability without its old
benign-context exclusions. Its own unsigned-image and hosts-file conditions
still apply, but a qualifying unsigned image with Microsoft version claims is
no longer excluded solely by that claim.
