# Node and Python stager review

The legacy group mixed source identifiers with activation chains. Payload
identifier combinations and HTTP-request clues now live under download and
execution profiles; the Python function identifier is classified as a name.
A file watcher, reads, and a silently loaded addon are a module-loading
profile; they do not establish that the watched bytes are the addon. PE
magic, launch APIs and masquerading filenames are process-artifact profiles
when the rules do not establish a payload chain. These weak combinations now
emit suspicious rather than hostile traits. The encoded `whoami` and command
execution combination is user discovery. The base64, temporary file and
detached launch combination remains an execution sink; the silent
curl-to-Node chain is network-sourced script evaluation.

The legacy dropper and Python staging directory consumers retain explicit
references to applicable moved rules; this preserves their alternatives while
their broader historical logic remains under review. Existing process-profile
references were updated when the 90-rule leaf was split by observed subject:
artifact, evaluation, hidden launch, process launch, shell and standard I/O.
No directory cap was changed.
