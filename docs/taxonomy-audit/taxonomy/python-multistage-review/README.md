# Python multistage delivery review

Image pixel access, EXIF reading, low-bit masking, paste-service addresses and DNS queries are reusable operations or observations. URL keys and an HTTP reference can co-occur without proving a staged download. The disjunction of these clues and its execution-adjacent consumer are described as data-retrieval profiles, not guaranteed multi-stage payload delivery.

The image URL, PNG parsing and Python execution combination remains an execution objective; so do PNG archive extraction with process execution and the embedded Python stage. Their descriptions do not imply data-flow proof the matchers do not require.

The crowded bitwise leaf was split into XOR, masking, shifting and mixed operations before adding the low-bit matchers. The two existing DNS TXT query alternatives already belonged to the DNS TXT directory, so their new aggregate does not widen that directory selector. The multistage legacy leaf is retired.

The profile parent hit its subdirectory limit. HTTP transfer and network context profiles now share subject-based parents; the upload and network leaves were split before they became crowded. Existing selectors and matcher-scoped file-type exceptions were updated to follow the moves.
