## Rule changes and boundaries

* Added encrypted JSP command-output handling, file-management APIs in that
  control protocol, and streamed AllPermission class loading in that control
  context. These require the existing abnormal equals/JSP/session/encrypted-reply
  channel, not names such as Cmd, a fixed cipher, destination, session key or
  package namespace. Behinder identity rules separately consume the new command
  behavior, recovering the missing Cmd family detections.
* Added notable Java bytecode observations for mkdir/mkdirs, filesystem rename,
  a setExecutable method-name constant, and an embedded Python PTY-spawn
  expression. They describe references rather than successful effects. Direct
  permission API descriptions were corrected to say references too.
* Moved reflective method resolution/invocation out of member inspection,
  Class.forName into JVM loading, and ProcessBuilder constructor/start evidence
  into subprocess creation. Updated all exact consumers. Ancestor selector
  searches found no lost reflection or launchagent selector consumers; the two
  exec directory consumers are JavaScript-specific, outside the moved class
  rule's scope. Effective types, platforms, exclusions and matcher evidence were
  preserved. The resulting claim sets were compared after applying moves.json.
* Moved generic RunAtLoad, KeepAlive and shell ProgramArguments observations out
  of LaunchAgent-specific placement into launchd configuration. The specimen
  installs a system daemon, so agent-specific names/descriptions misled triage.
* `.pwd`, `.username` and `.botid` references do not by themselves establish a
  password cache write, username collection or assigned bot identity/polling.
  Retained those same observations as notable path references in their subject
  homes; removed the bot-path test-directory exclusion. The specimen only reads
  `.botid` as an installation guard. Credential phishing, collection,
  exfiltration, daemon installation and other accurate attack findings survive.
* OpenRASP setter names plus reflection could also match protection-enabling
  setters. The disabling-setter rule now requires a true-value constant, while
  the guard-tamper rule additionally requires the null-target/false-object/call
  bytecode sequence seen in assigning AtomicBoolean(false). Generic constants
  and opcode fragments live in neutral metadata, separate from the attack claim.
  These are static combinations, not a general JVM data-flow proof; the field
  write shape is limited to this JVM compilation pattern. Both supported attack
  mechanisms still match the original specimen and renamed compiled variants.
* Inspecting the archive's non-requested Echo payload exposed a false hostile
  channel finding: its copied RunCMD helper is dormant. Reused the existing
  recognized Behinder Echo exception on the channel consumer. The exception
  needs the declared Echo identity and helper/cipher evidence and ceases to
  apply when RunCMD is referenced or active payload APIs appear. This is a
  narrow recognized-helper exception, not a universal unused-code analysis.

## Verification and remaining limitations

`python3 scripts/review/test-stranded-jvm.py --cleave
/usr/local/var/cyclotron/cleave/target/release/cleave --work-dir
/usr/local/var/cyclotron/tmp.noindex/cyclotron-60a42d22/scratch/stranded-review/jvm-tests`
compiles inert fixtures with javac --release 8, then statically scans them.
Fixtures exercise renamed classes, helpers and fields, a changed command and
session key, AES versus DES, streamed classes, file APIs, disabling versus
enabling OpenRASP settings, ordinary servlet/crypto code, inert name constants,
normal dotfile references, `.pwd.lock`, dormant Echo and an Echo variant that
actually invokes its command helper. They are never run. The original JVM
specimens and all three archives were also rescanned. No cross-language
coverage is claimed; runtime success on other operating systems was not tested.

JVM facts expose constant-pool method references and declarations but no flow
graph, call operands or per-method callee relationships. A general reverse-shell
matcher therefore cannot prove socket-to-process stream coupling from these
facts. A candidate paired-worker byte pattern was rejected: wildcarded constant
pool operands do not prove receiver/API identity, and a relay between unrelated
streams could share the shape. An engine fix must expose invocation targets,
receiver provenance and stream argument relationships from JVM bytecode. The
observed reverse-shell behavior is established by disassembly and remains
represented by the accurate encrypted shell-control finding; a dedicated generic
JVM reverse-shell technique remains a coverage gap.

OpenRASP, exer, uploadfile and index remain below three hostile traits. The first
has two actual bypass mechanisms; exer is a command relay; uploadfile is file
relay/result reporting; index is a dedicated operator inventory/control page.
No independent third attack was found in those bytes. Additional counts would
repeat those operations or assign helper behavior not present in the member.
For index, the two hostile identity findings do not supply generic enrollment
coverage: distinguishing arbitrary HTTP enrollment from webshell registration
without protocol/family constants requires stronger source flow/protocol models.
Existing PHP relay rules cover the supported WSO request shape; renamed generic
HTTP protocols are not claimed.

Atomscan's installed embedded engine rejects the repository's admitted
crypto/primitive and os/handler directories during automatic validation. For
reproducible before/after scans only, CLEAVE_VALIDATE=0 was used with the same
local rules, slow mode, no update, local analysis and no reference fetching.
The current release cleave binary validates and scans the complete rule tree.
Atomscan additionally warns that model v20.20 predates the v23 feature schema.
Writer remains a classifier miss at strict levels despite eight accurate hostile
traits: its matched level is L25. PHP members match L1, not L0. These thresholds
are reported instead of increasing scores through duplicate traits. Existing
JavaScript flow-analysis gap diagnostics are retained; they do not erase the
manually traced hex-table execution/export behavior.
